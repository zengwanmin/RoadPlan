# v1 独立审稿与数据审计报告

审查对象：`draft/v1_20260816` 中英文 LaTeX/PDF、`references.bib`、`DATA_AUDIT.md`、制图脚本，并回溯主实验、消融、多算法和敏感性实验源文件。本次未重跑高开销优化实验。

## 结论

**Major revision（接近 Reject and resubmit）。**

稿件的工程问题、DEM/OSM 数据驱动框架、当前主方案的基础数值和对局限性的坦诚程度较好，主题也基本符合 *Transportation Research Part C*。但现阶段不能以“IJS 已被严格证明优越”和“237 点支持当前模型稳健性”作为主要结论：算法实验的终点约束/密度口径与当前主模型不一致，且 IJS 与对照算法的 NFE 明显不等。此外，数学模型尚不足以独立复现，图版与投稿元数据也未到可投状态。

## Major issues

### M1（P0）验证链混用不同模型口径

当前主结果 `joint_results_w500_dens.json` 使用了端点高程锚定和建筑密度约束。但：

- 消融实验使用 `消融实验/objective.py`，其 `decode()` 将每个桩号高程独立映射为 `gz ± amp`，没有首末接线高程锚定，也不是当前的构造式坡度编码；它同时固定实测平面、不含密度分区。
- 多算法实验使用 `多算法对比/objective_joint.py`，其 `profile_from_grades()` 仍使用可自由调整的起点高程，未锚定终点，且无建筑密度约束。
- 237 点敏感性结果同样使用旧版 `敏感性分析（平、纵联合，重优化）/objective_joint.py`，没有端点锚定和密度约束。其基准为 C=23.6913 亿、E=13.6429 亿、Rmin=402.2 m，明显不是当前 M-C（24.2078/13.5278 亿，Rmin=420.9 m）。

稿件只将这些概括为“pre-density”，没有披露更关键的端点编码变化，因而会使读者误以为消融、基准和敏感性直接验证了当前密度版模型。

**必须修改：**最佳方案是用当前端点锚定、同一密度开关、同一目标/惩罚实现重跑消融、算法对比和关键敏感性。如暂时无法重跑，应把三者降级为“历史开发阶段的探索性证据”，不得用于支撑当前框架的稳健性结论。

### M2（P0）IJS 算法优势与额外 NFE 严重混杂

`algorithms.py` 显示，每代 JS 主移动消耗 1×pop 求值；+Lévy 或 +DE 变为 2×pop；完整 IJS 变为 3×pop，并额外有 1×pop Tent 初始候选。因此 500 代时约为：

- JS：100,200 NFE；
- JS+Lévy/JS+DE：200,200 NFE；
- IJS：300,400 NFE。

所以“IJS 相对 JS 提升 25.45%”和“DE 贡献 24.17%”不能解释为纯机制改善；它们同时包含 3倍/2倍求值预算。六规模算法对比也是同代数而非同 NFE，而且论文图注说“runtime and NFE are reported”，实际表 3/图 9 未给出任何 NFE 数值，只在正文中说“约两倍时间”。

**必须修改：**重跑等 NFE 实验（统一目标调用上限而非统一代数），同时报告实测 NFE、wall time、均值±标准差/中位数与 IQR、效应量和置信区间。在完成前，把结论改为“给定相同代数时 IJS 以更多求值获得更低 F”，不能宣称公平的算法优越性。

### M3（P0）统计检验名称、设计与报告不完整

- 消融表的 p 值由 `scipy.stats.mannwhitneyu` 产生；多算法表的 p 值由 `scipy.stats.ranksums` 产生。它们是两独立样本秩和检验，不是中文摘要声称的“配对 Wilcoxon”。实验又使用相同 run 编号、种群和种子，实际上具备配对设计。
- 五个消融比较和多算法对比未做 Holm/Hochberg 多重比较校正，未报告检验统计量和效应量。
- 正文只给出“best-of-10”表，却用它支撑稳定性/优越性。原始 CSV 实际已有 mean/std，应进入主表或补充表，不应只报最优种子。
- 当前密度版 M-C 只有一次优化，稿件已承认这一点，但摘要和结论的确定性表述仍过强。

**必须修改：**按设计选择配对 signed-rank/置换检验，或改为真正独立样本并正确命名 rank-sum；增加多重比较校正、效应量和 CI；对当前 M-C 至少做 20–30 个独立种子。

### M4（P0）数学模型还不能独立复现

当前正文只给出总成本式、简化断面式、跨越桥长式、货币化能耗总式和若干阻力式。以下关键内容缺失或只用“following Lin”带过：

- $C_R,C_B,C_S,C_Q$ 的完整方程、折现时序、单价和所有定标参数；
- 燃油率、EV 驱动/回收效率、方向处理的完整方程和参数表；
- 曲率、相邻坡差、斜交和密度惩罚的明确数学定义、$k_R,k_V,k_{skew},k_{forbid}$ 及两阶段惩罚的具体式；
- JS/IJS 更新式、Lévy 尺度、DE 变异/交叉式，以及边界处理；
- 熵权的完整算法、两次熵权（初始种群标量化权重和前沿决策权重）的区别，以及 Tier-1 软项在搜索与最终决策中的作用；
- 文中表 1 报告的 slope-hazard index $Q$的定义与权重。

另外，当前向量虽然存储 225 个纵断面数，但端点锚定后 `prof_norm[0]` 被完全忽略，因而实际有效纵断面自由度是 224，总有效维数是 274，而不是声称的 275。这个冗余维度也会影响算法对比的解释。

**必须修改：**增加完整符号/参数表和可独立实现的目标—约束—决策模型；删除被忽略的纵断面变量或将维数改为 50+224。

### M5（P1）“Pareto/IJS”叙事需要更精确

主实验不是一次直接产生非支配集的多目标 IJS，而是 21 个加权和标量问题的独立 IJS 搜索，再做可行—预算—非支配—熵权筛选。这是“weighted-sum Pareto approximation”，对非凸前沿可能遗漏解。图 3 中写“FEASIBLE KNEE SOLUTION”，但实际代码选的是预算门限后的熵权折中点，不是几何意义的 knee point。10% 预算容忍度也缺少政策/业主依据。

**必须修改：**统一术语，给出标量扫描的覆盖局限，更正流程图，并对 10% 预算门限做依据或敏感性分析。

### M6（P1）数据审计有一处明确数值错误，若干派生量需固化

- 原始 JSON 中 M-A `L_dense1_km=2.0101623393`，但 `make_v1_figures.py` 在输出 CSV 时手工写为 `2.001`。因此表 1 的 Tier-1 改善应为 **-20.85%**，不是 -20.5%。`DATA_AUDIT.md` 也把 M-A Tier-1 写成空缺，与 JSON 不一致。
- 4.08 km 跨越桥长度不在主 JSON 的 M-C 字段中，而是制图脚本调用当前 `crossings.py` 重算的派生值。这可复现，但应在审计表中记录代码版本/参数和原始输出，而不是只写“约 4.08”。
- `current_scheme_summary.csv` 只包含主表指标，消融、算法、敏感性的论文数值没有在版本目录中形成机器可读审计表，目前仍依赖外部历史目录。

**必须修改：**取消手写常数，所有论文数值直接从带哈希/版本号的原始 JSON/CSV 生成；生成一份完整 `paper_numbers.csv` 及自动断言。

### M7（P1）运输研究贡献需超越“元启发式算法排名”

选题符合 TR-C，但当前贡献和结果仍把大量篇幅用于 IJS 消融和六算法排名。一个 Tent+Lévy+DE 的组合元启发式对 TR-C 的方法新颖性可能不足，尤其当优势由额外 NFE 混杂时。更有价值的交通运输核心是：空间数据如何改变桥隧/城市暴露决策，平纵耦合为何改变可行性，以及成本—能耗交换的政策/设计含义。

**建议：**把 DEM/OSM 约束的增量价值做成组件消融（中线地形 vs 2D DEM，固定桥隧 vs 几何触发，无密度 vs Tier 1/2，单向 vs 双向能耗），并将运输工程发现放在摘要和讨论中心。

## Minor issues

### m1（P1）摘要过长且主张过密

英文摘要约 340 词，建议压缩至期刊当前 author guide 允许的上限（通常不超过 250 词）。保留问题、方法、当前主结果和一条稳健性证据；将细节性 p 值和 237 点移入正文。

### m2（P1）图版不符合可读性要求

英文 PDF 第 21–25 页集中堆放了大部分结果图，与正文引用处分离；第 24–25 页中 3D、消融、六面板收敛和敏感性字号过小，实际阅读时不可辨。第 6 页 `case_data_layers.png` 的轴、图例和图内标题也过小。图 4/5 尚可阅读，但同页排布仍偏拥挤。

**建议：**使用与正文接近的 8–10 pt 最终字号，拆分六面板图，给 3D/敏感性独立页宽，通过 `\FloatBarrier`/重排浮动体改善就近布局。保留用户要求的手绘科研风格，但应输出更高分辨率，并确保缩放后标签可读。

### m3（P1）中英文统计表述不一致

中文摘要写“配对 Wilcoxon”，英文实验协议写“Wilcoxon rank-sum”，必须与真实代码和重做后的设计统一。中英文其余主要数值和结论基本一致。

### m4（P2）引文可用，但尚非最终投稿品质

29 个 BibTeX 条目均在正文中被引用，核心 DOI/题名组合未发现明显伪造，且包含 2022–2024 的相关工作。但多个条目使用 `and others`，应替换为完整作者列表；缺少 2025–2026 的近期研究；本地学位论文、2025 广州造价指引和“独立项目信息”需要可访问的出处/存档链接。投稿前应用 Crossref/出版商页逐条再校验元数据。

### m5（P0，投稿前）占位符未清理

英文稿仍有 Anonymous Author(s)/institution、`[DATA-REPOSITORY-DOI-PLACEHOLDER]`、CRediT 作者占位、基金/致谢占位和未确认的利益冲突声明。如目标期刊采用双盲，作者信息应移到单独 title page，而不是在主稿中显示“Anonymous”。

### m6（P2）模板/编译细节

`elsarticle` 与 TR-C 匹配，PDF 可打开且引文可见。但版本目录保留的 `.log` 比最新 PDF 旧，包含 float-too-large/未定义引用等过时警告，不能作为最终 QA 依据。应清理辅助文件后从空目录编译中英文版，并保存与 PDF 同批次的无致命警告日志。

## 建议的修改顺序

1. **P0：统一模型口径。** 固化一个 endpoint-anchored+density 的权威 objective，用它生成主方案、消融、基准和敏感性。
2. **P0：重做等 NFE 算法实验和正确统计。** 优先 PJ5/PJ6 和主消融，然后扩展六规模；对当前 M-C 做多种子。
3. **P0：补全数学模型与参数表。** 删除冗余维度，使文稿可不依赖学位论文而复现。
4. **P1：修正 Tier-1 数值和全部数据血缘。** 论文数字由脚本生成，禁止手写转录。
5. **P1：重写摘要/贡献/讨论。** 弱化未经等 NFE 支持的排名宣称，强化 DEM/OSM 和平纵耦合对交通决策的含义。
6. **P1：重排图版。** 图就近、可读，修正“knee solution”错误。
7. **P0 submission check：** 替换占位符，完整引文元数据，干净编译，按期刊最新 guide 检查摘要、highlights、图像和双盲文件。
