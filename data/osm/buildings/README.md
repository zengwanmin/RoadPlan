# OSM 建筑轮廓（完整集）

**用途（严格限定）**：可视化图层 + 走廊带宽度的数据依据论证。
**不进入目标函数，不参与任何成本/能耗计算。**
这一限定是有意的 —— 见 [`../README.md`](../README.md)"为什么区别对待"。

## 完整性核验：三项计数逐项一致

**先定"标尺"再抓数**：先用 Overpass `out count` 取权威计数作硬指标，再分块抓取并
逐项对齐 —— 否则"抓了多少算全"永远说不清。

| 要素 | 实得 | `out count` 目标 | 结论 |
|---|---|---|---|
| `way["building"]` | 22414 | 22414 | 一致 |
| `relation["building"]` | 177 | 177 | 一致 |
| `way["building:part"]` | 397 | 397 | 一致 |

合计 22414 + 177 = 22591 个建筑要素，其中 **1 个几何退化**
（一个 relation 的成员无法缝成闭合环）被剔除，最终：

> **22590 个建筑、22787 个环、171039 个顶点、总占地 24.41 km²**
> （中位 519 m²，最大 145133 m²）

类型分布：`yes` 11407、`residential` 3526、`apartments` 3163、`commercial` 865、
`university` 660、`house` 547、`detached` 392、`school` 366 等。

## 抓取与处理

| 脚本 | 作用 |
|---|---|
| `fetch_buildings_full.py` | bbox 切 16×8 = 128 块，三类要素共 **384 次** `out geom` 查询；指数退避重试、端点轮换、分块落盘可断点续抓。**零失败** |
| `refetch_stale.py` | 重抓快照过期分块（见下） |
| `process_buildings.py` | 按 `(type,id)` 去重 → 多重多边形按 role 分内外环并**缝合成闭合环** → 质心/面积 → **与目标量逐项核对** |

bbox：`23.095, 113.159, 23.201, 113.423`（与 DEM、障碍物一致）。

## 快照一致性修正（一个容易被忽略的坑）

首轮抓取中镜像 `overpass.kumi.systems` 返回的是**它自己的旧快照**，27 个分块的
`timestamp_osm_base` 最早到 **2026-05-06**，比目标快照旧近 3 个月。
混用不同时刻的快照会使总数对不上（当时 way 少 10 个），且**数据自身不自洽**
（相邻块可能反映不同时点的地物）。

处理：`refetch_stale.py` 仅经主端点重抓这 27 块，并**断言返回快照日期**，
使全部 384 块的 `osm_base` 落在同一天；重新核对后三项计数全部一致。

> **教训**：镜像站点的数据新鲜度不保证与主站一致。凡分块抓取，
> **必须记录并校验每块的快照时刻**。

## 为什么必须用轮廓而不是质心

横向净距应量到建筑**边缘**而非质心。最大建筑占地 14.5 万 m²，其边缘比质心近上百米
—— 用质心会**系统性高估**可用宽度。按轮廓顶点重算的走廊带可行半宽
（两侧均无建筑冲突的里程占比）：

| 半宽 | ±100 m | ±200 m | ±300 m | ±500 m | ±800 m |
|---|---|---|---|---|---|
| 无冲突里程占比 | 71.6% | 58.0% | 49.3% | 34.6% | 18.2% |

左侧净距中位 550 m、右侧 719 m，**最紧断面仅 10 m**。
这组数据支持"走廊带不应全线取同一半宽"的结论。

### 旧文件的三处缺陷（保留仅为可追溯）

1. 用 `out center` 只存**质心**，没有建筑轮廓；
2. 只查 `way["building"]`，**漏掉 177 个多重多边形关系**；
3. bbox 被裁窄为 `23.1264~23.1966 / 113.1669~113.4137`，比 DEM/障碍物范围小一圈。

结果旧文件只有 **12789** 个点，**仅为实际 22414 个 way 的 57%**。

### `buildings_full.npz` 字段

| 字段 | 含义 |
|---|---|
| `poly_lon` / `poly_lat` | 所有环的顶点坐标（展平） |
| `poly_off` | 环的分界下标，长度 = 环数 + 1 |
| `poly_ring` | 每个环的类型，`outer` / `inner` |
| `poly_bid` | 每个环所属建筑在 `b_*` 数组中的下标 |
| `b_id` / `b_type` | 建筑的 OSM id 与类型（`way` / `rel`） |
| `b_lon` / `b_lat` | 建筑质心 |
| `b_area_m2` | 占地面积（m²，已扣除内环） |
| `b_building` | `building` 标签值 |
| `b_levels` / `b_height` | 层数与高度（缺失为 `nan`） |
| `b_name` | 名称（缺失为空串） |
| `part_*` | `building:part` 要素，同结构单独存放 |
| `osm_base` / `bbox` | 快照时刻与抓取范围 |

## 仍需注意的局限

数量已与 Overpass 计数完全一致，即**本 bbox 内 OSM 数据库中的建筑已全部取到**。
但 OSM 本身在国内城区的建筑测绘完备度并非 100%，因此**"图上空白"只能说明
OSM 中无记录，不等于实地无建筑**。此为数据源固有局限，非本次抓取的缺漏。

**正因如此，建筑轮廓本身不进入成本/能耗模型**；由其派生的密度分区只作
**可行性约束**（见下节），**不计拆迁费**，之前所有 C/E 结果保持可比。

## 密度聚类分区（V1 = 方案A，已选定）

方法、标定原理与局限详见
[`../../docs/数据来源与处理说明.md`](../../docs/数据来源与处理说明.md) §2.8。

三级分区：**Tier2 严格禁行**（硬约束）/ **Tier1 可穿越但抑制**（软代价，**不进 `pen`**）/
Tier0 自由。阈值由现状线位标定：`θ_forbid = 现状线位沿程最大密度 × margin`，
故 `margin ≥ 1` 时 **M-A 基准方案在 Tier2 上天然可行**，无需任何特例豁免。

### 6 个候选版本对比

| 版本 | 指标 / σ / margin | θ_forbid | Tier2 km² / 簇数 | Tier1 km² | M-A∩Tier1 km | ±500 最窄 m |
|---|---|---|---|---|---|---|
| **V1 ✅** | 占地覆盖率 / 200 m / 1.15 | 0.2111 | 27.29 / 35 | 62.25 | **2.000** | 625 |
| V2 | 占地覆盖率 / 100 m / 1.15 | 0.2880 | 15.44 / 103 | 51.63 | 0.850 | 600 |
| V3 | 占地覆盖率 / 300 m / 1.15 | 0.1722 | 38.23 / 16 | 70.22 | 2.312 | 675 |
| V4 | 栋数密度 / 200 m / 1.15 | 2.2555 栋/ha | 27.56 / 24 | 33.11 | 1.925 | 600 |
| V5 | 体量 / 200 m / 1.15 | 0.4914 | 58.80 / 21 | 28.07 | 0.425 | 1000 |
| V6 | 占地覆盖率 / 200 m / 1.00，无形态学后处理 | 0.1836 | 38.90 / 42 | 62.50 | 2.250 | 525 |

**选定 V1（方案A）**：街区尺度（35 簇）、`M-A∩Tier1 = 2.00 km` 如实反映"既有高速
确实穿过居民区"、走廊带仍留 625 m 可通宽度。

注意事项：

- **`M-A∩Tier2 = 0` 对 6 个版本全部成立**，是标定规则的必然结果（设计保证），
  **不能**用来论证某个版本更优。真正的区分量是 `M-A∩Tier1`、最窄可通宽度与禁区簇形态。
- 不同指标的 θ 数值**不可横向直接比较**（V4 单位为栋/公顷，V5 为等效层数）。
- **V5 证据不足**：仅 21.3%（4806/22590）建筑带 `building:levels` 标签，
  最大标注 103 层属异常，故体量指标未被选用。
- **阈值下界警告**：阈值取 **0.10** 会把 ±500 m 走廊带 **2 个断面完全封堵**，
  使走廊带内不存在可行线位，并导致 `run_joint.py` 的可行性门控取到空集后抛异常。
  任何新阈值方案采用前**必须**先跑 `corridor_passability` 检查。
