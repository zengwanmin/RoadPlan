# DEM 高程数据

详细说明见 [`../docs/数据来源与处理说明.md`](../docs/数据来源与处理说明.md) 第 1 节。

## 来源

- 数据集：AWS Terrain Tiles（terrarium 编码），公开免密钥、免注册
- 注册页：https://registry.opendata.aws/terrain-tiles/
- 瓦片 URL：`https://s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`
- 项目文档：https://github.com/tilezen/joerd
- 缩放级 `z = 14`；本纬度（23.16°N）像元约 **8.78 m**
  —— 但底数 SRTM 约 **30 m**，故 8.78 m 是像元尺寸而非真实分辨率（过采样约 3.4 倍）
- 解码：`h = R × 256 + G + B / 256 − 32768`

## 文件

| 文件 | 说明 |
|---|---|
| `走廊带DEM_z14_ext.npz` | **主用**。现状地表，1280×3072，字段 `elev/z/x0/y0/H/W` |
| `走廊带DEM_z14_ext_natural.npz` | **主用**。准天然地面 + 生态掩膜（派生），字段 `natural/eco/mask_half_w/eco_elev/eco_close` |
| `走廊带DEM_z14.npz` | 早期窄范围版本，仅历史可追溯 |
| `fetch_dem_ext.py` | 下载 60 张瓦片并拼接、坏点 3×3 中值填补 |
| `dem.py` | 双线性采样、准天然地面重建、生态掩膜、坐标换算 |

## 复现

```bash
python3 fetch_dem_ext.py
python3 -c "import dem; dem.build_natural(force=True)"
```

## 两处关键处理

1. **准天然地面重建**：现状路基已"长"在 DEM 里，会把现状方案的历史土方算成零，
   造成与优化方案的计费口径不公（系统性偏袒现状）。做法是把实测中线两侧 ±60 m
   掩膜移除后由带外邻域插值回填，此后**所有方案（含现状）统一对准天然地面**计算土方。
   这是插值近似，不是还原历史真实地面 —— 其作用是消除口径偏差。
2. **生态强制隧道区**：准天然地面高程 ≥ 70 m 的连片山体 + 约 500 m 形态学闭运算。
   双指标校准：面积 19.2 km²（实际约 21）、现状线穿越 1.28 km（实际隧道 1.35 km），
   两个独立指标都在 10% 以内。

## 可信度

沿实测中线采样 DEM 与 GPS 实测高程对比：**相关系数 0.915，中位偏差 +1.57 m**
（以常数 `BIAS_M` 消除该垂直基准差）。

## 已知局限

- 分辨率过采样（见上），适用于数百米尺度地形，不可用于微地形判读。
- **实际南界为 lat 23.09998，比标称 bbox 的 23.095 短约 555 m**
  （栅格取整 5 张 z14 瓦片 = 11238 m，而 bbox 需约 11800 m = 6 张）。
  线位 + ±2500 m 走廊带完全落在 DEM 内，不影响采样与优化；
  唯一后果是叠加图最南端一小片建筑没有地形底色。
